Pagination race: why a page number breaks and a cursor does not

Paging means loading a long list in small parts. This page shows what breaks when the list changes while the reader scrolls. Change one thing, then look at what happens.

How to use it

  1. Press Load next page. The phone gets 10 more posts.
  2. Press A new post arrives at the top. Then press Load next page again.
  3. Switch from page numbers to the cursor. Try the same steps.
  4. Allow double taps. Then press Tap Load next page twice, fast.
  5. Press A post is deleted on the server. Then press Load next page with page numbers, and look for a missed post.

      How the model works

      • The server has 60 posts, newest first. Post 60 is the newest. A new post gets the next number, 61, and goes at the top.
      • The phone loads 10 posts for each request.
      • With page numbers (offset), page 2 means rows 11 to 20 of the server list at that moment. The phone counts rows.
      • With a cursor, the server gives the phone a saved place after each page. The phone sends it back without reading it. The server sends the 10 posts after that place.
      • With one request at a time, a second tap is ignored while a request is running. The library does the same: it allows one running load for each direction.
      • Refresh drops the list on the phone and loads the first page again.
      • A repeated post shows more than once on the phone. A missed post is on the server, between the newest and the oldest post on the phone, but not on the phone. A new post above the newest post on the phone is not missed. It waits for a refresh.
      • There are no random numbers. The same steps always give the same result.

      What this model leaves out

      • A cursor does not stop every problem. If the server changes the ranking between two pages, a post can still repeat. The app removes repeats by post ID.
      • The model does not use a cursor that has expired, or a lost network. In the case study, an expired cursor gives a typed error, and then the app refreshes.
      • The model has no prefetch (loading before the reader asks). You press a button instead, so you can see each step. A fast scroll can send many requests for the same place, as the double tap does here.

About Mobile Design Rounds

Mobile system design interviews test how you build the client side of an app: storage, networking, background work, offline behavior and failure handling. Most prep material is written for backend engineers, so this site covers the mobile version, for Android and iOS engineers.

Who writes it

I'm Manuel Lorenzo, a professional Android developer, and I write this site with AI assistance. It's an independent side project and isn't affiliated with any employer. Don't take my word for it: every case study ends with a dated note on what was checked and what was not, with links to the official documentation it relies on. Corrections and questions are welcome as GitHub issues.

How the case studies are made

Drafts are written with AI assistance. Many technical claims are then checked against official documentation: the Android developer site for Android and Apple's developer documentation for iOS. Most snippets are compiled (Kotlin) or type-checked (Swift), with stubs for app-specific placeholder types, against the library and SDK versions named in each page's verification notes. Those versions are a snapshot from the date in the note and newer releases may exist. The exceptions and anything unverified are listed in the same notes, with dates. Where the official guidance is silent, the text says so.

The Android sections follow the official architecture guidance. The iOS sections are written by an Android developer from Apple's documentation, and have not yet been reviewed by an iOS engineer, so treat them as a careful second opinion, and tell me if something looks wrong.

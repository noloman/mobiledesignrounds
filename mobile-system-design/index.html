Mobile system design interview: the framework and every case study

Mobile rounds test the client. The client is the app on the phone. The round covers local storage, networking, background work, offline use, battery use and failure handling. There are no load balancers and no sharding. The case studies follow these five steps. Their numbered sections run in a slightly different order, because the architecture comes before the data model there. Several courses teach a five-step method. This one is my own, built from the case studies on this site.

  1. Scope and constraints: what the app must do, what it can skip, and the limits that shape the rest: offline use, battery and platform rules.
  2. Data and contracts: the data objects (entities), the API, and the IDs that make a retry safe.
  3. Client structure: UI, state holder, repository, local database, network, and who owns what.
  4. Make the hard part work: the send path, sync, caching or ordering, explained in full detail.
  5. Break it, ship it, roll it back: what fails, how you would know, and how to release the change and roll it back (undo it).

How a 45-minute round is spent

This is an example split. Companies differ, but the hard part always gets the largest share.

  • Scope and constraints4 min
  • Data and contracts10 min
  • Client structure8 min
  • Make the hard part work18 min
  • Break it, ship it, roll it back5 min

Mobile system design interview: the framework and every case study

Mobile rounds test the client: local storage, networking, background work, offline behavior, battery, and failure handling. There are no load balancers and no sharding. Each case study follows the same five steps.

  1. Clarify requirements: functional, non-functional, and what is out of scope.
  2. Draw the client architecture: UI, state holder, repository, local database, network.
  3. Define the data model and API: including the IDs that make retries safe.
  4. Go deep on the hard part: the send path, sync, caching, or ordering.
  5. Cover failure, offline and rollout: what breaks, and how you would ship it.

How a 45-minute round is spent

An example split. Companies vary, but the hard part always gets the largest share.

  • Requirements5 min
  • API and data model8 min
  • Client architecture10 min
  • The hard part17 min
  • Failure, offline, rollout5 min
